# 2026년 10월 1일 저녁 작업 기록

## 작업 범위

18시 이후 진행한 한국은행 349개 통계표 조회 보완, 화면의 분류 선택, 임베딩 인덱스 전환과 파일 정리를 정리했다. 이미 main에 들어간 Jev 하이브리드·출력 에이전트 작업은 이번에 새로 구현한 것으로 세지 않았다. 그 위에 StatBridge1의 완료 패치를 StatBridge-local1 구조에 맞춰 옮겼다.

StatBridge1의 검증·정리는 10월 1일 저녁에 진행했고, 저장소 이식과 다운로드 실행 경로 점검은 자정을 넘어 10월 2일까지 이어졌다. CSV의 내용은 원본 메타데이터와 맞췄으며, 기존 CRLF로 저장된 수동 Backend 메타데이터도 저장소 규칙에 따라 LF로 정리했다.

## 1. 목록에는 있는데 자료를 받지 못했던 두 표

먼저 상세자금순환의 잔액표 `DT_284Y001`과 거래표 `DT_284Y002`를 다시 확인했다. 예전에는 ITM 메타데이터에서 오류 30이 나서 조회 대상에서 제외했지만, 이번에는 ITM·PRD와 숫자 자료가 모두 응답했다. 언제부터 지원되기 시작했는지는 확인하지 못했다.

두 표의 2018~2024년 자료를 계정항목 50개와 제도부문 14개 조합으로 조회했다. 각 표에서 4,900개 숫자 자료를 받았다. 받은 메타데이터를 바탕으로 사전과 항목·분류·기간 CSV를 갱신하고, 두 표를 제외하던 코드와 카탈로그 전용 안내를 제거했다. 사전은 347개에서 349개, 버전 5.1로 바뀌었다. 숫자 원자료를 임의로 만들거나 다른 표로 대체하지 않았다.

검색 표현도 함께 손봤다. 상세자금순환의 잔액·보유액은 잔액표로, 거래·순거래는 거래표로 연결했다. 잔액인지 거래인지 없는 질문에는 둘 중 무엇을 원하는지 다시 묻는다. 표 ID를 직접 고르면 언어 모델이나 유사도 검색이 다른 표로 바꾸지 않도록 했다.

## 2. 349개 전수 조회에서 발견한 기본값 문제

두 표만 추가하면 끝날 것으로 생각했지만 첫 검사는 334/349였다. 실패한 15개는 기존 표였다. 사전의 첫 분류가 마지막 수록시점에 없는 경우와 필요한 분류가 누락된 경우를 따로 확인했다.

`DT_121Y007`은 최근 자료가 있는 대표 분류로 보정했고, `DT_404Y017`은 실제 API에서 확인한 `objL1=DATA`를 추가했다. 나머지 기업경영분석·구형 기업경기 표도 실제 숫자가 나오는 조합을 확인해 대표값을 지정했다. 과거 코드와 기존 동의어는 없애지 않았다. 대표값이 항상 전체나 합계라는 뜻은 아니므로 화면에는 실제 분류 이름을 표시한다.

보정 후 StatBridge1에서 다시 실행한 KOSIS 전수 조회는 **349/349**였다. 각 표의 사전상 마지막 수록시점과 대표 조합을 조회한 결과다. 모든 과거 기간과 모든 분류 조합을 전수 확인한 결과는 아니다.

## 3. 화면에서 선택한 분류를 그대로 조회하기

카탈로그의 금융·통화 → 상세자금순환에 두 표를 넣었다. 사용자가 계정항목·제도부문을 고르고 자료 조회 버튼을 누르면 기간을 선택하는 단계로 이어진다.

이때 분류 이름을 다시 검색하지 않고 `dimension_values`에 정확한 API 코드를 보낸다. 서버가 해당 표에 실제로 있는 코드인지 검사하고, 기간 입력 후에도 선택값을 유지한다. 비교용 기본값이 사용자의 선택을 덮어쓰던 경로도 수정했다.

자료를 받은 뒤 그래프 종류를 고르는 흐름은 유지했다. LangGraph에서 출력 에이전트로 넘기고, 제목·축 이름·범례 편집은 출력 설정을 통해 처리한다. 조회 실패는 `data_unavailable`로 표시하며 실제 자료가 없는 화면을 성공으로 보여주지 않는다.

## 4. 임베딩과 구형 파일 정리

신규·변경 문서는 CLOVA Studio Embedding v2를 호출해 임베딩했고, 바뀌지 않은 문서는 캐시를 재사용했다. 개념·통계표·분류 컬렉션은 각각 349개, 총 1,047개 문서이며 벡터는 1,024차원이다. 실제 임베딩·Reranker 호출에서도 순거래 질문은 거래표, 자산·부채 보유액 질문은 잔액표가 첫 후보로 나왔다.

기존 인덱스는 새 프로세스에서 HNSW 세그먼트를 읽을 때 오류가 났다. 원인을 특정 Windows 경로나 라이브러리 버전으로 단정하지 않고 새 `vector_store_349`를 만들었다. 새 프로세스에서 전체 읽기와 검색을 확인한 다음 기본 경로를 바꿨다.

검증이 끝난 뒤 미사용 구형 인덱스와 중복 백업 5개를 Windows 휴지통으로 정리했다. 현재 사전·메타데이터·새 인덱스·캐시·최종 검증 기록·API 키·실행환경은 남겼다. 기존 평가 기록은 불필요한 중복이라고 단정할 수 없어 삭제하지 않았다.

## 5. StatBridge-local1로 반영

원격 main에 기존 통합 PR이 병합된 것을 확인하고 그 상태에서 새 기능 브랜치를 만들었다. StatBridge1과 폴더 구조가 달라 경로를 그대로 복사하지 않았다.

- Agent 구현은 기존 `src/agent/agent_runtime.py`에 반영했다. 같은 이름의 모듈과 패키지가 충돌하지 않도록 기존 진입점을 유지했다.
- 실제 실행용 `data/runtime_data/processed/`와 수동 Backend용 `data/processed/`를 함께 갱신했다. 두 MCP 메타데이터 구현의 지원 목록도 맞췄다.
- 키가 없는 환경에서 제공하던 로컬 CSV 조회 경로와 조회 출처 정보는 보존했다.
- 전체 검사에서 연간 코드 `A`를 `Y`로 정규화하는 회귀와 UI 경고 누락을 확인해 수정했다. 화면이 비교 질문을 정해진 대출·금리 문장으로 바꾸던 코드도 제거했다. 원래 질문을 그대로 보내고 기존 LangGraph/Jev 경로에서 계열을 판단한다.

새 벡터 DB와 임베딩 캐시는 로컬 실행 검증에만 사용했다. 이번 커밋에는 `.env`, 키, 숫자 원자료 CSV, 벡터 DB, 생성된 평가 결과를 넣지 않는다. 비공개 평가 저장소와 holdout 정답은 읽거나 사용하지 않았다.

## 6. 다운로드 후 CMD 실행

GitHub ZIP을 압축 해제하고 루트의 `START_STATBRIDGE.cmd`를 더블클릭하는 경로를 정리했다. Python·Node.js·가상환경·필수 패키지를 검사하고, 미설치 환경은 가능한 경우 winget·pip·npm으로 준비한다. Python/Node 설치 후에는 경로를 갱신해 이어서 진행한다.

API 키가 없으면 예시 설정에서 `.env`를 만들고 메모장을 열어 입력을 안내한다. 빈 값이나 예시 문구는 실제 키로 인정하지 않는다. 벡터 인덱스는 파일 존재 여부만 보지 않고 현재 사전과 문서가 일치하는지 검사한다. 없거나 불완전하면 캐시를 활용해 생성하고 새 프로세스에서 다시 읽어 확인한다. 최초 생성은 최대 1,047개 임베딩 호출로 시간과 API 사용량이 든다.

준비가 끝나면 Agent API·MCP·UI를 백그라운드로 실행하고 브라우저를 연다. 종료 명령은 이 실행기가 기록한 프로세스만 종료한다. PID가 재사용됐을 가능성도 확인한다. 다른 프로그램이 포트를 사용하고 있으면 강제로 종료하지 않는다. 로그는 `evaluation_runs/`에서 확인할 수 있다.

.\.venv_runtime\Scripts\python.exe TEST_349_TABLES.py
