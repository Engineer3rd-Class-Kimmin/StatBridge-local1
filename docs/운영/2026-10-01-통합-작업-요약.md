# 2026-10-01 StatBridge 통합 작업 기록

오늘 작업은 새 PC에서 실행할 수 있는 통합 패키지 정리, 그래프 출력 역할 분리, HCX-003과 Jev 비교평가, Jev 보조 판정 적용, StatBridge-local 동기화 순서로 진행했다. 실제 API 키, 가상환경, node_modules, 빌드 결과는 업로드 대상에서 제외했다.

## 실행 패키지 정리

StatBridge1의 실행 코드를 StatBridge-local의 `src/agent`, MCP 실행 자료를 `data/statbridge_mcp_server`, 메타데이터를 `data/runtime_data`에 배치했다. 루트의 `START_STATBRIDGE.cmd`는 Python, Node.js, 가상환경과 의존성을 검사하고 빠진 항목을 설치한다. KOSIS와 NCP 키가 없으면 `.env` 작성 위치를 안내하고, 설정 후 Agent API·MCP·UI를 실행한다.

`.venv_runtime`은 각 컴퓨터에서 다시 만드는 환경이므로 ZIP 전달이나 GitHub 업로드에 넣지 않는다. 삭제 후 실행하면 설치 과정과 인터넷 연결이 필요하다. `.env`의 키와 프로젝트 코드·메타데이터는 보존해야 한다.

## 그래프 출력 역할 분리

UI는 질의 입력, 역질문 선택, 조회 기간, 그래프 종류와 편집 옵션 선택을 담당한다. 데이터를 조회한 뒤 `need_output_config`를 반환하고 사용자가 선택해야 그래프를 만든다. `output_agent.py`의 `OutputAgent`가 데이터 계열 정리, 그래프 종류 선택, 요약, 편집 명세를 담당한다. `POST /api/output`과 LangGraph의 `await_output_selection`, `prepare_output`을 연결했다.

기존 통계 검색 에이전트에서 직접 출력하던 경로는 출력 에이전트 호출로 바꿨다. 표 탐색, clarification, 확정 조건, 기간 처리, MCP/KOSIS 조회는 기존 경로를 사용한다. 프론트엔드도 조회 후 출력 선택 화면을 거치도록 반영했다.

## HCX-003과 Jev 비교평가

실제 통계언어 사전의 routing example 29개를 3개 표현으로 변형한 87문항과 복수지표 13문항을 합쳐 100문항을 사용했다. 모델마다 각 문항을 3회 실행하여 300회씩 비교했다. HCX-003의 JSON과 Jev의 choice/Yes-No 결과를 공통 분야·의도·조건·주기·지표 개수로 변환해 같은 정답으로 채점했다.

| 항목 | HCX-003 | jev-latest | jev-preview |
|---|---:|---:|---:|
| 분야 정확도 | 98.00% | 91.00% | 91.33% |
| 의도 F1 | 64.23% | 59.88% | 60.43% |
| 조건 F1 | 93.33% | 93.18% | 93.29% |
| 명시 주기 정확도 | 100% | 100% | 100% |
| 지표 개수 정확도 | 28.00% | 95.67% | 96.33% |
| 정상 출력률 | 99.00% | 99.67% | 100% |
| HTTP API 오류율 | 0% | 0.33% | 0% |
| p50 | 4.009초 | 0.261초 | 0.261초 |
| p95 | 5.036초 | 0.390초 | 0.341초 |

최초 Jev 호출은 `options` 필드 때문에 HTTP 422로 실패했다. API 요청을 `criteria`로 수정한 뒤 재평가했고 최초 실패 실행은 성능 비교에서 제외했다. HCX의 저장 응답은 보존했다.

원본 평가 방법은 `docs/운영/hcx003-jev-비교평가-방법.md`, 재현 자료는 `eval/hcx003-jev-comparison`에 있다. HCX 결과·고정 프롬프트·정답·채점 코드와 정상 Jev 응답을 함께 보관했다. `hcx-role`의 당시 summary에는 스키마 오류 실행도 기록되어 있으므로 Jev 성능은 `jev-role/results/jev_only_20261001_124316`을 기준으로 확인한다.

## Jev 패치

HCX-003이 분야와 검색 언어를 구조화한 뒤 Jev가 독립 지표 개수만 판단하도록 붙였다. 기본 모델은 `jev-preview`다. 원질문을 우선하고 HCX concepts, measures, series를 보조 입력으로 보낸다. 허용하는 개수는 0·2·3·4·5다.

0이면 series를 비우고, HCX 개수가 일치하면 유지한다. 부족한 경우 HCX가 추출한 지표명이 안전하게 구분되는 경우에만 보정한다. 근거가 부족하면 `not_safe`로 원본을 보존한다. 여러 지역의 같은 지표와 전년 대비 계산을 별도 지표로 세지 않도록 판단 기준을 명시했다. 실적/전망처럼 서로 다른 표로 조회하는 계열도 기준에 포함했다.

키 없음, timeout, HTTP 오류, 잘못된 응답은 HCX 원본으로 fallback한다. `STATBRIDGE_JEV_ENABLED=0`이면 호출을 생략한다. 정확 일치 사전 fast path도 HCX와 Jev를 생략한다. trace에는 모델, 상태, 지연, 판정 개수, 보정 전후 개수, 보정 동작, fallback 여부를 남긴다.

StatBridge-local의 설정 위치는 `data/statbridge_mcp_server/.env`다. 기존 파일에 아래 값을 추가하면 된다. TypeSafe 키가 없어도 HCX fallback으로 실행된다.

```dotenv
TYPESAFE_API_KEY=
TYPESAFE_ENDPOINT=https://api.typesafe.ai
STATBRIDGE_JEV_MODEL=jev-preview
STATBRIDGE_JEV_ENABLED=1
STATBRIDGE_JEV_TIMEOUT=10
```

## 패치 후 평가와 수치 해석

| 항목 | HCX 기존 300회 | 저장 응답 보정 300회 | 최종 Jev 실호출 100회 |
|---|---:|---:|---:|
| 최종 series 개수 정확도 | 28.00% | 98.00% | 100.00% |
| 정상 HCX 출력률 | 99.00% | 99.00% | 99.00% |
| p50 | 4.009초 | 4.283초 | 4.180초 |
| p95 | 5.036초 | 5.305초 | 5.251초 |

최종 100회는 저장한 HCX repeat-1 결과에 현재 Jev 프롬프트를 실제 호출하여 보정한 결과다. 서비스 전체를 100번 실행해 표 ID나 그래프까지 맞힌 비율은 아니다. 지연시간도 저장 HCX 시간과 이번 Jev 호출 시간의 합이며 전체 UI 응답시간과 구분한다. 이번 Jev 100회 호출의 실패와 fallback은 0건이었다.

최초 하이브리드 100문항에서 기업경기 실적/전망 1건을 놓쳤고, 그 결과를 본 뒤 판단 문구를 보완하여 같은 정답셋을 다시 실행했다. 따라서 최종 100%는 개발 중 사용한 평가셋에 대한 확인 결과이며 독립 holdout 성능으로 해석하지 않는다. 87문항도 서로 독립인 87개 업무가 아니라 29개 질문의 표현 변형이다. 4·5개 지표는 이 Gold Set에 없다.

기존 구현 보고서와 하이브리드 summary의 `api_error_pct=1.0`은 HTTP 오류와 구문/출력 오류를 구분하지 않고 invalid 출력을 집계한 값이다. 원본 HCX HTTP 오류율은 **0%**, 비정상 출력률은 **1%**다. 두 수치를 구분해 사용한다.

## 실제 실행 확인과 남은 문제

StatBridge1에서 경제심리지수 `DT_513Y001`을 실제 MCP/KOSIS로 조회해 12행과 출력 결과를 확인했다. 기준금리 포함 두 지표·세 지표 질문은 Jev가 각각 2·3으로 판정했지만 사전에 기준금리 표가 없어 `no_match`였다. 서울·부산 CPI는 series 0으로 보정했지만 현재 사전에서 최종 표 탐색에 실패했다. 이 세 질의의 최종 조회를 성공으로 기록하지 않았다.

StatBridge-local로 옮긴 뒤에도 임시 HTTP 서버에서 health, 347개 사전 로딩, 경제심리지수 조회를 확인했다. `/api/query`가 `need_output_config`를 반환했고 `/api/output`에 선 그래프를 주문하자 `resolved`와 차트 1개를 반환했다. 검증 서버는 종료했다. 검증 시 TypeSafe 키는 기존 로컬 평가 환경에서 프로세스에만 불러왔으며 저장소의 `.env`를 덮어쓰지 않았다.

Agent 흐름, clarification 회귀, LangGraph, 출력 에이전트, 신규 Jev 14개 테스트와 프론트엔드 production build는 통과했다. 별도 데이터 수집·일일 기록·Gold Set 도구 테스트는 33개 통과, 3개 skip, 7개 subtest 통과였다.

전체 `tests/`는 구버전 `statbridge_agent.models`, `hcx`, `jev`, `experiment` 패키지를 참조하는 테스트 10개의 수집 오류가 있었다. 구버전 package version 테스트 1개도 현행 단일 모듈과 맞지 않아 실패했다. 오늘 이식한 기능의 회귀 테스트는 통과했지만 전체 저장소 테스트가 모두 통과했다고 기록하지 않는다. 구버전 테스트와 현행 실행 모듈의 이름 충돌 정리는 후속 작업으로 남겼다.

## StatBridge-local 반영 범위

`src/agent`의 출력 에이전트, Jev 모듈, bridge API, LangGraph, UI 변경을 가져왔다. 로컬 저장소의 환경 파일·메타데이터·테스트 경로는 `src/agent`, `data/statbridge_mcp_server`, `data/runtime_data`에 맞췄다. 테스트, Gold Set, 평가 실행 코드·결과, 구현 보고서, 구조 문서를 함께 반영했다. 기존 Git 이력과 런처 경로는 유지했다.

최종 판단은 **PASS WITH LIMITATIONS**다. 하이브리드 보정과 출력 선택 흐름은 구현·검증했으며, 미지원 표 탐색과 구버전 테스트 충돌은 남아 있다.
