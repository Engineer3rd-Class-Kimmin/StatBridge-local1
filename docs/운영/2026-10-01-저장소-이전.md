# StatBridge-local1 저장소 이전 기록

폴더 이름을 StatBridge-local에서 StatBridge-local1로 바꿔도 `.git`의 원격 주소와 커밋 이력은 바뀌지 않는다. `nothing to commit`은 파일 변경이 없다는 뜻이며 다른 저장소에 업로드했다는 뜻은 아니다.

기존 origin은 `Engineer3rd-Class-Kimmin/StatBridge-local`이었다. 이 주소는 `previous-origin`으로 보존했고, 새 origin을 `https://github.com/Engineer3rd-Class-Kimmin/StatBridge-local1.git`으로 연결했다. 기존 완료 상태 `dc3cb2c`는 로컬 `backup/statbridge-local-completed` 브랜치에 보존했다.

두 저장소는 공통 조상이 없는 별도 이력을 갖고 있다. 새 저장소의 `main`을 기준으로 `feat/portable-jev-output-integration` 브랜치를 만들고 기존 완료 코드와 운영 문서를 이식했다. 원격 main을 강제로 덮어쓰지 않았다.

새 저장소에는 `statbridge_agent/` 패키지가 이미 있었다. 이를 유지하면서 현재 통합 `StatBridgeAgent` 코드는 `agent_runtime.py`로 반영했다. HTTP API와 신규 테스트도 해당 모듈을 참조한다. 기존 패키지용 테스트와 현행 런타임이 같은 이름으로 충돌하던 문제를 피한다.

이식 검증에서 새 main이 이미 처리하던 조건도 보존했다. 카탈로그 전용 표는 UI의 name/item/unit 계약으로 반환하고, 조회 실패는 `data_unavailable`로 표시한다. KOSIS 키가 없을 때 외부 CSV를 선택하는 조건과 source 계보를 유지한다. 프론트엔드가 대출/금리 비교 질문을 고정 문장 두 개로 바꾸던 경로를 제거하여 원질문이 HCX/Jev로 전달되게 했고, API 경고도 화면에 표시한다.

이식 범위는 통합 Windows 런처, 공개 메타데이터, MCP 런타임, HCX-003/Jev 보정, LangGraph, 출력 에이전트, UI, 오늘 작업 요약, 공개 비교 평가 자료와 실행 코드다. 비공개 holdout 답안·결과와 기존 전체 Git 이력은 새 원격에 가져오지 않았다. `.env`, 가상환경, node_modules, 벡터 DB와 원자료 CSV도 커밋하지 않는다.

새 저장소에서 검증한 결과는 기존 tests와 공개 v4.1 tests 27개 통과, 신규 Jev 14개 통과, Agent/clarification/LangGraph/출력 스크립트 통과, v4.1 validator 통과, UI production build 통과다. 실제 임시 HTTP 서버에서도 health와 경제심리지수 조회 후 `need_output_config`, 선 그래프 주문 후 `resolved`와 차트 1개를 확인했다. 이전 작업 요약의 구버전 테스트 수집 충돌은 이전 저장소 당시 기록이며, 새 저장소에서는 기존 패키지를 보존하여 해당 이름 충돌을 해결했다.

새 저장소에서 기존 main 코드를 보존한 채 PR로 변경을 검토할 수 있다. 현재 작업 브랜치를 clone하려면 다음 명령을 사용한다.

```powershell
git clone --branch feat/portable-jev-output-integration https://github.com/Engineer3rd-Class-Kimmin/StatBridge-local1.git
cd StatBridge-local1
.\START_STATBRIDGE.cmd
```
