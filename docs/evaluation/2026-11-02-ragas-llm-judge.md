## RAGAS 관련 변경

요약이 가운데점 뒤의 구성 항목·지역·계산명을 잃지 않도록 하고, 원계열·조정계열의 축약명이 겹치면 원래 명칭을 유지한다. 표시 시작점과 시차·이동 계산에 필요한 선행 조회기간을 구분한다. 연도가 생략된 뒤쪽 월·분기와 단일 숫자로 요청한 기간 통계의 표시기간도 처리한다.

`rolling_sum`, `rolling_median`, `rolling_range`는 전체 달력 창을 검증한다. 결측을 제외한 부분 통계로 대체하지 않는다. 정의만 하고 계산·출력에 쓰지 않은 입력은 필수 파일 보완 대상에서 제외한다. 경제심리지수 원계열의 빈 API 단위는 정확히 일치한 기관·표·항목·분류·주기에만 공식 정의를 연결해 계산용으로 보완하며 원응답을 보존한다.

`tools/ragas_execution_scope.py`는 각 표시 시점·값을 같은 실행의 공식 API 행 또는 실행된 계산 결과에 연결한 후 기간 근거를 만든다. 수록기간, 실제 조회기간, 설정된 표시기간, 실제 표시 관측시점은 별도 필드다. 질문·정답·생성 요약·Judge 판정을 근거 생성 입력으로 받지 않는다. 실행·문항 ID와 파일 해시는 호출하는 평가 어댑터가 먼저 검증해야 한다.

평가 입력 버전은 `request_response_metadata_scope_v3`로 구분한다. 표준 Faithfulness의 주장 추출·NLI 프롬프트·모델 설정은 바꾸지 않는다. 이 도구 추가 자체가 전체 평가 어댑터 적용이나 실제 재채점 완료를 뜻하지 않는다. 같은 응답에 근거만 보완한 점수 변화와 제품을 수정해 새로 생성한 응답의 변화도 분리해야 한다.

세부 계약과 재현 방법은 [기간 근거 구성](ragas-period-evidence.md), [제품 보완 기록](../implementation/2026-11-02-ragas-report-patch.md)을 따른다.

## LLM Judge 기준과 최초 평가

v3 기준은 질문에서 기대 기간·필수 계열을 도출하고, 실행별 관측 형태·증거 경로·캡처 범위를 따로 연결한다. 요청 반영의 명확성, 근거 확인의 용이성, 표의 이해 용이성, 그래프의 전달력, 결과 활용성을 각각 1~4점으로 평가했다. 정성 채점과 정확성 검산은 별도 단계다.

선택 열과 권장 0 기준선의 부재만으로 감점하지 않는다. 출처는 실제 화면에서 확인하기 쉬운지를 평가하며, 내부 JSON에만 있는 문장을 화면에 표시된 정보로 간주하지 않는다. 과거 실행의 캡처 제한을 새 실행에 복사하지 않는다.

## 단위 검토 수정과 후속 평가

계획 검토 문맥에 `workflow_stage=plan_before_source_fetch`와 `observation_unit_validation`을 추가한다. 단위 근거가 아직 없으면 `pending_source_fetch`, 이미 제공되면 `preflight_evidence_available`로 명시한다. 조회 전 빈 목록만으로 계획을 거부하지 않도록 의미 검토 지시를 보완했다. 실제 수식·선택 자료·경제적 의미의 불일치는 계속 거부한다.

이 변경은 단위를 만들어 넣거나 검증을 생략하지 않는다. 실제 조회·계산 단계에서 단위가 비거나 섞이면 실행을 중단한다. 합성 회귀 테스트는 조회 대기와 사전 단위 근거의 전달, 승인된 계획에서도 실제 단위 오류가 계산 엔진에 도달하지 않는지 확인한다.

| 문항 | 최초 점수 → 후속 점수: 요청·근거·표·그래프·활용성 | 후속 관찰 |
|---|---|---|
| Q05 | `2·1·1·1·1` → `4·3·3·4·4` | 수정 후 별도 실행. 2021~2024년 48개월 원금리·전월 차이 출력 |
| Q06 | `2·1·1·1·1` → `4·3·4·4·4` | 수정 후 별도 실행. 2015~2024년 10개 연간 GDP·증가율 출력 |
| Q10 | `3·3·3·2·2` → `4·3·3·3·3` | 같은 저장 응답의 스크롤 보완 증거로 재평가. 증가율 패널·축·기간·출처 확인 |

Q01~Q04·Q07~Q09는 다시 실행·채점하지 않았다. 위 후속 점수를 최초 실행의 다른 문항과 합쳐 단일 실행 10/10 성공이나 합격률로 주장하지 않는다. Q10의 변경은 새 증거에 따른 판정 수정이며 제품 개선 점수가 아니다.

Q04는 공통 y축에서 서울·부산의 규모 차이 때문에 부산 추이를 읽기 어렵다는 관찰이 남았다. 계산 근거의 내부 별칭·코드형 식, 복수 기준연도·단위와 분산된 근거 위치도 개선 대상이다. Q10은 내부 스크롤로 아래 패널을 볼 수 있지만 처음부터 두 패널을 동시에 보기 어렵고 약어 눈금이 남는다.

## 저장 수치 검산

Claude가 작성한 검증 코드는 제품의 전체 정밀도 표·그래프 값을 10월 27일 동결 참고 원자료와 독립 산식 재계산에 대조했다. 제품 계획은 정답으로 쓰지 않았다. 허용 오차는 값 자체 단위에서 `abs(actual - expected) <= 1e-6 + 1e-10`이며, 양쪽 모두 결측일 때만 결측이 대응한다.

| 실행 | 검산 대상 | 비교 값 수 | 관측된 최대 절대 차이·불일치 |
|---|---|---:|---|
| 최초 실행 | 출력이 있는 8문항 | 1,620 | 0 · 0건 |
| 수정 후 별도 실행 | Q05 48개월·Q06 10년 | 174 (144 + 30) | 0 · 0건 |

값 수에는 표와 그래프의 중복 표현이 포함된다. 고유 질문 수·독립 표본 수로 해석하지 않는다. 계열·분류·기간·주기·단위·계산 선행 입력도 확인했다. 수정 후 검증기 v2는 그래프 축 단위 검사와 연간 `A`/`Y` 정규화를 추가했다. 저장된 변조 시험 기록은 기간 누락·중복, 수치·단위·결측 변조의 검출을 다룬다.

검산은 별도의 11월 2일 공식 API 독립 재조회가 아니다. 화면의 반올림 표시값과 관찰되지 않은 요약문 수치는 범위 밖이다. Q04 서울 값은 `answers.md`에 별도 수치가 없어 동결 `observations.json`에만 대조했다. 최초 실행 Q05·Q06에는 검산할 수치가 없었다.

## 근거 보존과 재현의 한계

검토한 로컬 묶음은 `StatBridge_LLM_Judge_share_20261102.zip`이다. SHA-256은 `7aacdb849f0e93f4ce9d838fcb921fc9a5ba4ff98c09a5aa422e86f0f31d6074`이며 165개 파일을 담고 있다. ZIP 무결성과 manifest의 파일 해시를 이번 PR 준비에서 다시 대조했다. v3 결과 레코드는 정성 최초 10건·보완 3건, 정확성 최초 10건·수정 후 2건으로 총 25건이다. 이는 실행 문항 수 25개를 뜻하지 않는다.

원본 정성 판정·정확성 결과는 덮어쓰지 않고 보존했다. 제품 실행·캡처·수정 전후 수집·스크롤 검사는 Codex, 기준 구조화·정성 채점·정확성 검증 코드와 결과는 Claude가 수행한 기록이다. Judge의 세션 설정 ID는 `claude-opus-5-5`로 기록됐지만 실제 응답 모델은 미확인이다. 사람 3인의 평가로 표현하지 않는다.
