# 팀원 v2: 평가셋 보완과 편집·파일·파생 개선

2026-10-27 · ai-assisted · 사람 정답·최종 결과 승인 대기

## v1에서 확장한 목적과 준비 검토

같은 작성자의 v1을 확장한 편집 20·화면/파일 20·파생 20문항이다. 복수 수정의 상태 보존, 부분 범위, 저장/재개, 서로 다른 revision의 다운로드와 연산 순서가 추가됐다. 두 금리·6개월의 고정 공개 fixture를 사용한다. 별도 고난도 조회셋 v2.1과 구분한다.

원본 준비 검증은 60문항 구조, 20개 계산의 스키마·기간·수치와 관련 33개 회귀 통과를 서술했지만 실제 모델 계획·UI 60문항 성공을 뜻하지 않았다. 독립 검토에서는 질문에서 직접 옮긴 Decimal 식으로 20문항·75개 출력값을 검산했고 오차 1e-6 이내였으나 다음 한계를 확인했다.

| 원본 평가셋의 부족한 점 | 평가 전에 보완한 내용 |
|---|---|
| D26/D28의 차분과 단순 이동평균은 주어진 조건에서 교환 가능해 숫자로 순서를 구별 못함 | D28·D30을 비율, 이동평균, 상대 증감률의 순서가 결과를 바꾸는 조합으로 변경 |
| D29·D31 등 일부 문항의 복잡도가 낮음 | 2개월 대비 상대 변화, 서로 다른 창의 평균 비율로 변경 |
| D37/D38 재지수화 배율은 상대 증감률에서 소거됨 | 동치 계산을 허용하고 중간 난이도 기준 2문항으로 명시. 보완본은 고난도 58·기준 2 |
| 전체 다단계 문장을 한번에 입력하면 후속 조건이 앞선 확인 질문에 노출됨 | 총 164개 실행 단계와 단계별 기대 상태를 분리하고 현재 단계만 전달 |
| E33에서 무엇을 반드시 물어야 하는지 모호 | 대상·범위 확인은 필수, 강조 방법 확인은 선택으로 명시 |
| 준비 검사가 정답 계획·전체 fixture를 사용 | 실제 모델 계획을 실행하고 요청한 기간만 공급하는 경계와 선행 월 기록 추가 |

이는 **평가셋 개선**이며 제품 실패 후 질문을 고쳐 성공률을 높인 작업과 구분한다. 보완본 60문항으로 최초 실제 구성요소 평가를 시작한 뒤에는 같은 문항·정답으로 제품 패치를 비교했다.

## 보완본의 첫 실제 실행

| 실패 문항 | 실제 관측 | 제품 개선 |
|---|---|---|
| F21 | 제목 안에 크기 지시까지 포함되고 폰트는 20 유지 | 복합 문장에서 제목 문자열과 폰트 크기 속성 분리 |
| F26·F27·F37 | 구간/한 관측점 스타일의 SVG/PDF 내보내기 HTTP 422 | 화면과 동일한 구간·점 스타일 결정을 인쇄 렌더러에도 적용 |
| F28 | PDF 메모 중심이 목표 (0.90, 0.10)에서 벗어남 | 화살표 없는 메모에 오프셋을 적용하지 않고 중심 좌표 사용 |
| D30 | 최초 응답 미완료. 진단 재시도도 계산 확인에서 중단 | 특정 잘못된 순서의 금지를 전체 계산 보류로 읽지 않도록 문맥 처리 |

D30 진단 재시도는 최초 점수를 대체하지 않았다. PNG는 실제 Chrome의 제품 `workspacePng` 함수를 실행했고 서버 인쇄 출력과 별도로 검수했다. 최초 기록은 파일 36개, 그림/문서 23개 시각 검수, CSV/XLSX 13개·102값 비교를 서술한다. SVG dash의 미리보기 도구 차이는 제품 실패로 세지 않았다.

## 패치 후 확인과 남은 범위

최종 새 60문항 코호트는 전 영역 20/20, 파일 40개 검증으로 기록되어 있고 현재 점수 JSON과 일치한다. F28의 메모 중심은 (0.900116, 0.102541)로 오차 0.03 이내였다. v2.1과 함께 수행한 당시 전체 회귀는 2,369개와 subtest 355개 통과, 빌드·v4.1 검증 통과다.

공통 초기 상태는 fixture와 제품 출력 엔진으로 구성했다. 모델/API·파일 평가이므로 로그인부터 시작하는 UI 전수·실제 마우스 선택·다운로드 이벤트·이미지 이해 성공으로 확대하지 않는다. 라이브 KOSIS 최신 수치, 전체 지표 다양성, 서버 재시작 뒤 저장 복구도 이 점수에서 보장하지 않는다.
