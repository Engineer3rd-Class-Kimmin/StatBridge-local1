## 실제 실행과 검수 범위

- 파생: 질문 → 실제 모델 계획 → 승인 메타데이터 검증 → 원자료 조회 경계 → 계산 → `/api/query`·`/api/output`. 정답 계획 주입 없음. 실제 공급 요청 기간을 기록하고 그 기간의 fixture만 공급했습니다.
- 편집: 제품 조회 계획과 출력 엔진으로 공통 초기 차트를 구성한 뒤 실제 `/api/output/edit`와 모델/제품 규칙 경로를 실행했습니다. 제목·색·두께·기간·부분 범위·숨김·이력·복원을 단계별로 비교했습니다.
- 초기 공통 상태는 평가용 fixture입니다. 사용자 로그인 화면·자연어 초기 조회·선택 버튼의 UI 연결은 이 점수 범위 밖입니다. UI 선택/되돌리기/표 설정/저장·재개는 해당 백엔드 계약으로 재생했습니다. 그림 표시는 구조화된 선택 정보만 제공했으며 실제 마우스 표시·이미지 이해는 미평가입니다.
- PNG: 서버 인쇄 경로와 다른 실제 프런트엔드 `workspacePng` 함수를 격리된 Chrome에서 실행했습니다. 생성된 13개 PNG를 디코딩하고 시각 검수했습니다. 다운로드 버튼과 브라우저 다운로드 이벤트는 미평가입니다.
- 파일 36개 확보: PNG 13, SVG 6, PDF 4, CSV 8, XLSX 5. 필수 SVG/PDF 4개는 422로 생성 실패. 확보된 그림·문서 23개를 시각 검수하고 CSV/XLSX 13개의 102개 값을 날짜·계열별로 대조했습니다. XLSX는 숫자 셀과 표시 순서도 확인했습니다.
- 최초 실행기의 출처 캡션 누락과 적용 후 그림 표시 해제 동작을 수정한 뒤 편집·파일 40문항 전체를 새 초기 상태에서 다시 실행했습니다. 최종 코호트는 `edit-complete-fixture`, `file-complete-fixture`, `derived-final`입니다. 이전 성공을 골라 합치지 않았습니다.
- SVG의 dash는 Chrome 렌더링과 SVG 속성으로 확인했습니다. PyMuPDF의 SVG 미리보기에서 dash가 실선처럼 보이는 렌더링 차이를 제품 오류로 집계하지 않았습니다.
- 공통 출처를 명시적으로 준비했기 때문에 인쇄 PDF/SVG에는 같은 출처가 두 줄 나타날 수 있습니다. 출처 누락·다른 출처로 보지 않으며 픽셀 동일성은 요구하지 않습니다.

## 결과의 의미와 제한

v1과 같은 고정 한국은행 금리 두 계열·6개월의 공개 개발 평가입니다. 오늘 KOSIS 원자료를 실시간 조회한 성능이나 비공개/블라인드 성능이 아닙니다. 승인 메타데이터는 로컬 카탈로그를 사용했습니다.

v1의 기존 60/60은 실제 UI 실행 보고이고 이번 결과는 모델/API·파일 구성요소 평가이므로 점수를 직접 빼서 성능 하락 폭으로 해석하면 안 됩니다. 실제 UI 전수 판정과 사람 정답 승인은 남아 있습니다. 이번 작업에서는 제품 코드를 수정하지 않았습니다.

데이터 검증은 통과했습니다. 제품 코드 변경·PR 제출이 없는 평가 작업이므로 전체 pytest, v4.1 평가 검증, 프런트엔드 전체 빌드를 이번에 다시 실행하지 않았습니다. 실제 사용한 모델/API 실행과 생성 파일 검수 결과만 위 수치에 포함했습니다.
