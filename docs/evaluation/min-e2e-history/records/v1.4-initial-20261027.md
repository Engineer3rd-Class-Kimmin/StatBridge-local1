## 정답 입력 차단과 실행 범위

실행 준비에서는 ZIP의 questions.md만 읽어 ID와 질의만 있는 questions.jsonl을 만들었다. 제품 실행기는 이 JSONL만 읽는다. 50개의 최초 /api/query 요청을 검사했으며 모두 원문의 query와 execute:true 두 필드뿐이다. 과거 대화, 선택지, 정답, 참고 표·그래프와 ZIP의 관측값은 전달하지 않았다. /api/output의 자연어도 원문 질의만 사용했고 그래프 종류·배치는 제품의 기본 자동 출력 정책이 선택했다.

각 문항은 격리된 테스트 계정의 새 Chrome 브라우저 컨텍스트에서 시작했다. 실제 프런트엔드 입력창과 분석하기 버튼으로 질의를 제출하고, 제품이 자동 조회·계산·출력한 뒤 그래프와 표 탭을 각각 열어 화면·DOM 표·Plotly 시점과 값·실제 API 응답을 보존했다. 로그인 준비, 저장·다운로드·편집은 이 E2E 채점 범위 밖이다.

제품은 실제 모델과 KOSIS를 호출했다. 원자료 fixture, 정답 계산 트리, 수정 질의, 추가 답변 또는 재시도를 주입하지 않았다. 제품의 실제 20초/120초 UI 시간 제한을 늘리지 않았다. 기존 349개 표의 실제 API 메타데이터 캐시는 사용했지만 첨부 ZIP의 observations.json을 원자료로 사용하지 않았다.

모든 응답·캡처의 SHA-256을 prediction-freeze.json에 확정한 다음에만 별도 scoring-only/에 정답·참고 HTML·rubric을 준비해 채점했다. 첨부 fetch.py/render.py는 실행하지 않았다. 정답 확인 후 제품 재실행이나 제품 패치도 하지 않았다. 이 결과 ZIP에는 scoring-only/ 및 첨부 정답·참고 파일을 포함하지 않는다.

## 채점 근거

완료된 16문항은 기관·표·항목·분류·주기와 전체 기간의 876개 원수치를 대조했다. 실제 DOM 표의 값과 Plotly 선의 전체 시점·값도 비교했으며 기본 절대오차는 0.000001이다. 그래프·표 캡처 32개를 모아 축·단위·범례·출처·표시를 시각 점검했다. 이 16문항은 A~E 정량 조건을 충족해 각 100점으로 기록했다. 최종 사람의 정성 검토는 대기다.

출력 없이 멈춘 문항은 필요한 최종 표·그래프가 없다는 직접 증거로 시스템 미통과를 기록했다. 보이지 않은 계열 선택·시점·수치를 임의로 틀렸다고 만들지 않아 A~C는 미판정, D/E는 출력 미생성으로 0%다. 다섯 항목을 모두 판정하지 못한 문항의 100점 총점은 산출하지 않았다. 따라서 50문항의 평균 점수도 산출하지 않는다.

41번은 예외로 검토 대기다. 질문은 부산/서울 비율과 전월 대비 변화를 요구하지만 정답은 비율의 % 표시와 변화의 %p 차이를 고정한다. 제품은 배율/% 및 차이/상대증감률을 확인했다. 전달 README도 이 문항을 정합성 검토 대상으로 명시한다. 표·그래프가 미완료라는 실행 사실은 보존하되, 이 확인 질문을 제품 오답으로 확정하지 않았다. 질문·정답·기준을 임의 변경하지 않았다.

17번은 화면의 20초 제한 도달이 직접 관측돼 UI 미완료로 처리했다. 서버의 후속 결과나 외부 API 장애 여부는 관측하지 못했으므로 원인을 지어내지 않았다. 확인된 외부 장애를 제품 오류로 바꿔 집계한 사례는 없다.

## 재현·산출물

원본 질문과 실행 입력의 해시는 input-manifest.json, 제품 파일의 실행 전 해시는 product-source-hashes.json, 입력 격리 검사는 isolation-verification.json에 기록했다. 최초 결과는 predictions/에 문항별로 있으며 실패 화면도 포함한다. 제품 코드 변경·PR 제출 없이 평가만 수행해 전체 pytest·빌드를 다시 실행하지 않았다. 앞선 코드 검증 결과를 이번 50문항의 성공으로 계산하지 않았다.

재실행은 키가 구성된 동일 저장소에서 새 평가 디렉터리와 격리 DB를 준비해 serve.py로 제품과 기존 프런트엔드를 띄우고 run_ui.py를 실행한다. 브라우저 테스트 의존성은 기존 evaluation_runs/team-v2-evaluation-20261027/browser-deps를 사용했다. 질의 실행이 끝나고 prediction-freeze.json이 생성된 후 prepare_scoring.py와 score.py만 별도 단계로 실행한다. 기존 최초 결과를 덮어쓰지 않는다.
