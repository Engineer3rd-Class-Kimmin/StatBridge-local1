# 지원용 프로젝트 설명: StatBridge

## 문제와 접근

통계표 이름이 비슷해도 원계열·계절조정, 평잔·말잔, 통화·지역·기간이 다르면 결과가 달라진다. 자연어 질문을 표와 계열 선택으로 연결한 뒤, 한국은행 KOSIS 원자료를 조회하고 계산 근거와 출처를 보여주는 흐름을 만들었다. 모델이 제안한 식은 서버에서 출처·단위·주기·계산량을 검증한다.

## 기여 범위

팀 프로젝트의 Backend·Data·MCP 영역과 개인 로컬 후속 개선을 구분해서 설명한다. 검색·메타데이터·자료 조회 도구와 API 연결이 백엔드 설명의 중심이다. 로컬 후속 작업에는 그래프 편집 복구, 파생지표 계산·파일 보완, Windows 실행 경로와 공개 개발 평가가 포함된다. 기존 코드 전체를 개인이 처음부터 작성했다는 뜻은 아니다.

팀의 영역 구분은 [팀 일정](팀-프로젝트-일정.md), 코드 위치는 README의 코드와 데이터 표, 후속 구현은 [동적 파생지표 설계](implementation/2026-10-19-dynamic-derived-design.md)에 연결했다. 팀 일정은 계획 문서이므로 실제 개인 기여의 단독 증빙으로 사용하지 않는다. 개별 변경의 범위는 구현 기록과 해당 Git 변경 이력으로 확인해야 한다.

## AI 활용과 검증

제품에서는 자연어 질의·계열 선택과 파생 계산 계획, 그래프 수정 등에 모델을 사용한다. 관측값을 모델이 생성하도록 두지 않고 승인된 API와 명시적 업로드로 제한한다. 모델 역할은 각 구현 경로의 문서에서 확인하며 한 모델이 모든 단계를 처리한다고 요약하지 않는다.

개발에서는 LLM·에이전트로 코드를 수정하고 회귀를 확인했다. 이번 문서도 Codex로 작성했다(ai-assisted). 계산 결과는 원자료·산식·상태 변화로 검증하고, UI는 실제 브라우저와 API 흐름에서 확인한 기존 기록에 연결했다. 사람의 정답 승인과 개발 평가 통과를 구분한다.

## 기존 평가 결과를 읽는 방법

| 평가 | 기존 기록 | 한계 |
|---|---|---|
| 최소 E2E v1 | [60문항 UI 결과](../eval/min-e2e/v1/FULL_UI_REPORT.md) | 개발셋·고정 원자료 기반 경로를 포함하며 v1.1과 실행 조건이 다름 |
| 최소 E2E v1.1 | [40문항 UI 결과](../eval/min-e2e/v1.1/FULL_UI_REPORT.md): 최초 응답 재채점 21/40, 패치 후 40/40 | 실제 KOSIS·모델·브라우저 기반의 개발 회귀. 사람 공식 승인 대기, 블라인드 일반화 성능 아님 |

이번 작업은 포트폴리오 문서 정리이며 위 E2E를 새로 실행한 작업이 아니다. 평가 버전별 점수를 합산하지 않고, local1의 결과로 StatBridge1 동기화나 모든 배포본의 동작을 주장하지 않는다. v1.1의 40문항은 편집·다운로드·다중 턴 재개까지 검증한 결과가 아니다.

## 결과와 남은 문제

자연어에서 자료 확인·계산·시각화로 이어지는 경로와 실패 후 복구 근거를 남겼다. 한편 승인되지 않은 라벨, API 변경, 자료 미확보, 단위 확인이 필요한 요청은 여전히 검토 대상이다. 최신 원자료를 쓰는 평가와 고정 응답 재생을 구분해야 하며, 원래 자료가 없을 때 다른 출처를 조용히 대신 사용하지 않는다.

## 공개 범위

이번 변경은 이 문서와 README 링크뿐이다. 비공개 평가 저장소·보류 정답, API 키, 사용자 계정·저장 그래프, 원자료 CSV, 원본 실행 로그를 추가하지 않는다. 신규 평가 결과를 이 저장소에 게시하는 변경이 아니다. 기존 공개 평가 보고서만 연결한다.
