# 질의 문맥과 파일 출력 보완

2026-10-27 · ai-assisted · 사람 코드·판정 검토 대기

## 문제와 변경

제목·후보 목록·취소한 검토안에 있는 계산 단어와 계열 이름이 실제 요청으로 처리되었다. 이 때문에 일반 조회가 계산으로 분기하고, 제외된 계열을 함께 가져오거나 이미 지정한 기준을 다시 물었다. 같은 사용자의 문장을 분류기·카탈로그·기간 파서가 서로 다르게 읽는 문제도 있었다.

`query_semantics.active_request()`가 현재 유효한 제약을 정리한다. 인용 자체를 삭제하지 않고 주변의 제목·후보·폐기 문맥을 확인하므로 실제 인용된 지표·분류와 앞선 합의는 유지한다. 일상어의 평잔·말잔·신규취급액 표현을 정규화하며 차주 종류를 추가하지 않는다. 입력 문자열만 사용하는 순수 함수이고 동일 입력을 처리하는 한정 크기 캐시를 사용한다. 생산 코드에 평가 ID·정답 수치·문항별 계획을 넣지 않았다.

`operation_text()`와 기존 분기 함수는 공표값 조회, 부정한 연산, 다음 작업의 연산과 현재 계산을 구별한다. 같은 비중의 기간 대표값, 1을 기준으로 한 배율, 100을 기준으로 한 재지수화, 두 값의 간격, 중앙 위치와 범위 등 간접 계산 표현을 인식한다. 특정 계산 순서를 금지한 문장은 별도의 긍정 계산 요청을 취소하지 않는다. 명시적으로 계산을 보류한 요청과 후속 계산 재개는 기존 정책을 유지한다.

조회에는 같은 유효 조건을 적용한다. 표의 이름과 실제 분류·주기는 현재 메타데이터에서 선택한다. 미정인 금리 기준·계절조정·통화·비교·집계 기준을 질문하고, 조건이 이미 정해졌으면 재질문하지 않는다. ‘첫 석 달’과 ‘첫 분기’를 1~3월로 읽고 SNA 기준연도·수록 시작연도를 관측 기간과 구분한다. 최신 관측을 요청한 계열은 현재 달까지 실제 원자료를 확인한다.

원자료 확인 검색은 여러 단어가 표명과 분류에 나뉘어 있어도 같은 메타데이터 안에서 확인한다. 큰 후보 집합에서는 검색 근거가 많은 후보를 제한해 의미 검증하고, 잘린 후보에서 확정하지 못한 결과를 자료 부재로 단정하지 않는다. 기관·표·항목·분류 검증과 원자료 조회 경계는 유지한다.

복합 제목·글꼴 크기 요청은 제목 문자열과 속성을 각각 적용한다. SVG/PDF는 화면과 같은 구간·관측점 스타일 결정을 사용한다. 화살표가 없는 메모는 화살표 오프셋을 적용하지 않고 지정 좌표의 중심에 놓는다. 부분 스타일이 있는 비지원 그래프 종류·비선형 연결은 계속 명시적으로 안내한다. HTTP 요청·응답 스키마는 변경하지 않았다.

## 개발 평가

질의만 모델·제품 입력에 제공하고 응답을 저장한 후 별도 채점했다. 공개 개발셋을 보고 수정한 회고적 결과이며 블라인드 성능으로 해석하지 않는다. 역질문 의미 판정과 코드의 사람 검토는 대기 상태다.

v2.1의 조회·역질문은 실제 `/api/query`와 KOSIS 원자료, 유형 분류는 제품의 로컬 분기 함수를 실행했다. 새 최종 60문항 코호트 전체를 실행했다. 최신월 문항은 원계열만 202609까지 조회했고 독립 API 조회와 일치했다. 관측값·원자료 스냅샷을 생성하거나 정답으로 주입하지 않았다.

팀원 v2는 기존과 같은 두 금리·6개월 고정 원자료 fixture와 실제 모델·편집·계산 API로 60개를 실행했다. 파일 40개와 실제 Chrome의 제품 PNG 함수를 검증했다. F28의 PDF 메모 중심은 목표 (0.90, 0.10), 측정 (0.900116, 0.102541)로 허용오차 0.03을 충족했다. 서로 다른 평가 계열의 점수를 합산하지 않으며 두 평가 모두 전체 UI 클릭 E2E 범위를 뜻하지 않는다.

## 검증과 재현

평가 응답·원자료·인증 DB는 Git에서 제외하는 `evaluation_runs/`에 보존한다. 최종 질의 SHA와 응답·파일 해시를 기록했다. 원본 평가셋·이전 평가 결과를 덮어쓰지 않았다.

- v2.1: `evaluation_runs/v21-patched-final-20261027/`의 `run.py`, `verify_latest.py`, `score.py`.
- 팀원 v2: `evaluation_runs/team-v2-patched-20261027/`의 `run_derived.py`, `run_edit_file.py`, `check_browser_png.py`, `score.py`.
- 회귀: `tests/test_scoped_query_semantics.py`, `tests/test_export_edit_consistency.py`와 저장소 전체 pytest·v4.1 검증·프런트엔드 빌드.

최종 전체 회귀는 2,369 passed 및 355 subtests passed다. 저장소의 테스트 파일 126개를 네 개의 독립 pytest 프로세스로 나누어 빠짐없이 실행했다. 초기 전체 실행에서 발견한 계산 보류 관련 회귀 7건은 수정 후 관련 파일 70개 테스트와 최종 전체 실행에서 재확인했다. v4.1 검증과 프런트엔드 `corepack pnpm build`도 통과했다. Vite는 샌드박스의 하위 프로세스 실행 제한(EPERM) 후 허용 환경에서 같은 빌드를 실행했으며 기존 큰 번들 경고는 남아 있다. 라이브 모델·KOSIS 결과는 실행 시점에 따라 달라질 수 있다.
